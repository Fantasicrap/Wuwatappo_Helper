# 房间内存优化

仅供娱乐使用，创作者概不负责。

适配官方 1.0.3，Helper 版本号保留 1.0.3.2；本次随按需运行优化一起覆盖 GitHub 同版本附件。

最新的按需运行优化文件：`dist/idle-optimized-1.0.3.2/Wuwatappo_Helper-1.0.3.2.exe`，详见[按需运行优化说明](按需运行优化说明.md)。之前第二版文件位于 `dist/memory-optimized-2-1.0.3.2`。原发布文件和前两版优化包保留。

## 改动

- 原来房间隐藏通过透明度实现，角色、配件和表情图片节点仍在页面内，素材预加载也会处理隐藏成员。
- 优化后，一键隐藏或单独隐藏成员会卸载其图片内容，保留固定尺寸的位置外壳与房间成员数据，恢复显示时重建图片。
- 预加载只处理可见成员；隐藏或离开后清理对应就绪标记，正在加载的旧批次完成时不能恢复隐藏成员的就绪状态。
- 隐藏期间跳过该成员新表情的图片与清理定时器分配。仍接收房间状态，恢复显示后显示后续收到的表情。
- 保留持续隐藏、新加入与离线重连隐藏、单独显示例外、自己的桌宠和按键映射。
- 第二版移除各 WebView 启动时对整套界面图片的后台预加载，由实际显示的图片元素按需请求；首次打开部分界面可能需要等待图片加载。
- 第二版启动器改为流式读取、哈希校验和解包内嵌程序，避免为约 78 MB 包体创建多个大数组。缓存文件仍按 SHA256 校验，损坏后重新释放。

## 对比方法

1. 完全退出旧版及托盘桌宠，运行测试文件。首次启动仍使用原有 Windows UAC 确认。
2. 进入同一房间，尽量保持成员数量、角色和缩放相同，等待素材加载完成。
3. 分别记录显示成员、一键隐藏后等待 30～60 秒、重新显示后的桌宠 WebView2 进程内存。
4. 重复开关数次，检查位置、显示恢复、新成员隐藏和内存趋势。需要与旧版对照时，先完全退出再换 EXE。

WebView2 可能暂时保留解码缓存和 GPU 分配，移除图片节点不保证任务管理器数值立即下降。多进程工作集相加可能重复计算共享内存；GPU 进程的工作集也不等于显存。不要混入 Windows 搜索及其他应用的 WebView2。

## 验证范围

18 项自动脚本通过，包括提取实际补丁渲染函数验证隐藏时不调用图片/表情解析、预加载排除与恢复、旧加载结果失效、房间重连隐藏、页面正常挂载且不调度全量图片预加载，以及已有设置界面和录制相关回归。启动器内嵌包体和原版六档图标单独校验。

第二版隔离测试验证首次流式解包与原件哈希一致、缓存命中不重写、同长度内容损坏后可修复。该次测试测得解包步骤托管堆增量为首次 287328 字节、缓存命中 20440 字节；这是测试宿主里的步骤测量，不代表完整 Helper 或 WebView2 的总占用。

未自动操作真实账号房间，未替用户退出当前程序，未测得真实房间中的内存下降幅度。没有使用强制清空工作集、禁用 GPU 或终止 WebView2 进程的办法。
