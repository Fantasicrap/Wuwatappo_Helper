# 长时间挂机：自动宝箱与登录状态

适用：Helper v1.0.3.4 同版本修复。此文记录客户端已复现的问题和修复边界，不代表已在真实账号连续挂机多天。

## 自动宝箱

1. **网络异常状态可能无法恢复。** 原版网络模块在一次健康检查开始后的一秒内，如果再次报告请求失败，会先清除旧的重试，再因去重直接放弃新检查。这时状态可能永久停在 `degraded`，即使网络可用，自动宝箱仍因网络门禁停止。修复为保留一个延迟检查，等待去重间隔结束后执行；系统时间回拨也不会把检查推迟一天。
2. **首次校时失败缺少定时补偿。** 宝箱在成功读取服务器时间前处于准备状态；首次请求失败后，原逻辑主要等待登录或网络状态变化。自动宝箱现在会在联网、登录且初始化结束后每隔至少 30 秒重试校时。
3. **长时间暂停后的时钟衔接。** 自动任务发现超过一分钟的执行间隔，或系统时间与单调计时明显不一致，会先重新读取服务器时间，并重新等待至少五秒。领取后的冷却截止值统一使用已校准的服务器时间，避免休眠时性能计时暂停导致冷却额外延长。
4. **不重复提交。** 左右宝箱串行领取；请求仍未返回时不因挂机超时强行解除锁。失败后每侧至少间隔 30 秒重试；恢复网络后重新等待五秒。保留原版领取条件、点击数消耗和服务器结果处理。

自动领取仍须手动开启。点击数低于原版最低要求（当前为 1000）、已退出登录、仍断网或服务器维护时，暂停领取属于预期行为。长时间无输入会持续消耗已有点击数，点击数用完需要补足。

## 登录与续期

- 原版续期成功只重写 `lastLoginTime`，没有刷新 `infoToken` Cookie 的七天保存期限。已用原代码模拟复现“续期成功但第八天登录 Cookie 消失”。现改为仅在官方续期返回成功、且账号未变化时同时刷新两个 Cookie；本地到期估计从本次成功续期时刻起计算，不在旧的未来日期上反复累加。
- 主窗口复用已有一秒任务，每分钟检查是否需要续期。令牌尚未接近原版两天阈值时不发送续期请求；关闭自动宝箱仍会保留登录维护。断网不清除登录，续期传输失败至少等待 30 秒再试。
- 原版把没有业务错误码的 HTTP 403 也视为登录无效。现在普通 403 保留为请求错误；明确的 HTTP 401、业务错误码 10002／10003 仍按官方流程清除失效登录，要求重新登录。
- 带旧账号凭据的迟到响应不能清除新登录；异步加载退出模块后再次检查登录，避免延迟退出新账号。等待续期期间若账号改变，取消原请求，不把它发送到新账号。
- 服务器主动撤销会话、真实过期、其他设备登录等情况是否发生，仍需要该用户出错时的服务端返回或本机日志判断。本修复不绕过服务端认证，也不保证永不退出登录。

## 诊断与验证

沿用原版日志通道，新增 `HELPER / auto_chest` 的恢复、校时及重试事件，以及 `AUTH / session_invalid` 的明确失效业务码。新增日志不包含令牌、账号 ID、库存或真实按键。

- `node scripts/test-long-run.cjs`：四天虚拟时钟循环、384 次模拟领取、初始化失败重试、断网恢复、休眠、时间回拨、五秒等待、账号切换和待返回请求防重复。
- `node scripts/test-session-lifetime.cjs`：原版 Cookie 丢失复现、八天虚拟时钟续期、普通 403 与真实认证失败区分、续期退避和迟到响应保护。
- `node scripts/test-network-recovery.cjs`：原版永久异常门禁复现、去重后保留重试及系统时间回拨。

这些测试不向官方服务器发请求，不代表真实账号挂机四天或八天实测。若仍复现，请记录是否能手动领取、左右宝箱倒计时、剩余点击数、当时是否锁屏／休眠／断网、登录失效提示及发生时间，便于与日志对应。
