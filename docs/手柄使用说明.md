# 手柄显示、校准与录制

**仅供娱乐使用，创作者概不负责。**

Helper 1.0.3.1 为官方 WuwaTappo 1.0.3 增加 SDL3 手柄采集。这里的“映射”是把实体控件对应到桌宠上的显示和录制控件；不会修改游戏的键位，也不会向游戏注入操作。原程序已有的手柄点击计数继续由原来的处理器负责，新增采集不会重复增加点击数。

## 开始使用

1. 完全退出官方版和旧版 Helper，包括托盘进程，然后运行新版 `Wuwatappo_Helper.exe`。
2. 官方内层程序声明需要管理员权限，Windows 可能弹出 UAC 确认。确认后才能启动；取消则结束此次启动并清理手柄服务。Helper 不修改 UAC 设置，安装包本身仍无需管理员权限。
3. 用 USB、接收器或蓝牙连接手柄。第三方设备优先选择 PC / XInput 模式；连接模式按对应型号说明书切换。
4. 展开计数器左侧的键盘按钮，点击上方“手柄”。设置中的“桌面键盘映射”也有这个选项。
5. 按键会高亮；双摇杆显示二维位置；LT/RT（PS 布局为 L2/R2）在顶部独立扳机键中显示连续百分比与填充进度。L1/R1 为肩键，L3/R3 为摇杆按下。松开后恢复。拔出后清除高亮并结束当前录制。
6. 点击设备名称可轮换已连接的设备，一次显示、录制一只。点击右上角布局按钮可轮换自动、Xbox、PS、Nintendo、通用标签。布局只改变文字，不会改变游戏按键。

暂未连接手柄时，界面会给出检查连接和输入模式的提示。原生服务最多枚举 16 个设备，按设备 ID 分开处理；同一只实体手柄如果被转译软件创建了虚拟副本，需要自行选择其中一个。

## 品牌与连接模式

以下是接入路径与使用建议，并非逐型号实测认证。本机没有连接实体手柄，已完成原生 SDL 初始化和模拟输入测试。

| 设备 | 建议路径 | 注意事项 |
| --- | --- | --- |
| Xbox 360 / One / Series 及兼容设备 | Windows 可识别的 XInput 模式 | USB、官方接收器或支持的蓝牙连接；老型号的无线连接方式不同 |
| PS4 DualShock 4 / PS5 DualSense | SDL 的 PS HID 支持，先尝试 USB，再测试蓝牙 | 自动显示 × / ○ / □ / △、L1/R1、L2/R2；若运行 DS4Windows、Steam Input 等转译软件，可能同时看到虚拟 Xbox 手柄 |
| 北通鲲鹏、阿修罗等 | 对应型号的 PC / XInput / 接收器模式 | 鲲鹏是北通系列。鲲鹏 20 的说明书列有接收器、XInput 蓝牙、Switch 蓝牙及 BFM 等模式；不同型号切换方法不同，不统一写死按键组合 |
| 飞智 | 设备支持的 PC / XInput 模式 | 专用软件、手机映射或键鼠模式不一定以手柄设备出现 |
| 盖世小鸡、八位堂等 | PC / XInput 优先；SDL 可识别的 Switch / HID 模式也可尝试 | Nintendo 字母位置与 Xbox 不同，按实际识别结果选择布局 |
| 其他 DirectInput / HID 设备 | SDL 通用摇杆回退 + 手动校准 | 显示 B0 等通用标签；默认轴顺序未必正确，需要逐项学习 |

Windows 必须先识别设备。可按 Win+R，输入 `joy.cpl` 检查是否存在设备及其属性响应。厂商驱动、固件、蓝牙适配器和输入模式都会影响结果。背键若只复制普通键，不能区分为独立背键；只有系统和 SDL 暴露的独立按钮才能单独显示。

## 标准控件与显示

标准采集最多包含 26 个数字控件及 6 条轴：A/B/X/Y、Back/Guide/Start、L3/R3、LB/RB、方向键，以及设备支持的附加键；6 条轴为左右摇杆 X/Y、左右扳机。未按下的附加键默认收起。触摸板只在 SDL 提供数字按键时显示点击；不采集触摸坐标、陀螺仪、加速度、麦克风、震动或自适应扳机效果。

Xbox 的 A 和 PS 的 × 对应同一标准位置 B0。TXT 同时包含标准编号与当次选用的标签，例如 `B0(A)` 或 `B0(×)`。通用摇杆底层最多读取 64 个按钮、16 条轴和 4 个方向帽，再通过校准对应到上述标准控件。

## 校准

点击“选项”打开设备诊断和校准。配置按 VID、PID、名称组合保存到本机应用偏好；同型号同名称的设备共享配置，切换连接模式可能生成另一份配置。

1. 点击“目标 A”依次选择要显示的标准按键。点击“按键/轴”切换到轴目标，再点击目标按钮轮换左右摇杆 X/Y、左右扳机。
2. 先松开实体控件，再点击“学习”，随后只按下一个实体按钮、方向帽方向，或明显移动一条轴。程序将这个物理控件绑定到所选显示目标。
3. 摇杆方向反了，选中该轴后点击“反向”。让摇杆回到中心，再点“中心/零点”保存两个摇杆当前的中心偏移。
4. 扳机可分别在完全松开时点击“中心/零点”，完全按下时点击“设满”；必要时先反向。范围无效时输出为零，应重新设置两端。
5. 漂移时点击“摇杆死区”轮换 8%、12%、18%、25%，默认 12%，采用径向死区。扳机有独立的死区选项（0%、2%、5%、10%，默认 2%），滤除松开时的微小抖动，保留连续百分比。配置不合适可点击“恢复该设备默认”。

修改校准、切换设备或重置配置会先结束当前录制。校准不会修改驱动、固件或游戏设置。“轴”诊断显示应用归一化后的状态，便于检查对应关系。

## 录制与 TXT 导出

在手柄界面点击“开始录制”，或使用独立录制快捷键 **Ctrl+Alt+F10**；再次触发结束。手柄界面使用这组快捷键录制手柄，其他键盘界面沿用鸣潮专属录制。可在设置中修改快捷键并检查冲突。

只有明确开始后才建立记录。一次记录当前选择的一只手柄，不混入键盘或鼠标操作。状态栏会显示录制时长与事件数。结束后点击“导出手柄 TXT”，文件名为 `Wuwa-手柄录制-<时间戳>.txt`，UTF-8 带 BOM，记事本可以直接查看。

TXT 包含 UTC 开始时间、设备名、输入模式、初始状态、相对毫秒时间、按下/松开、按住时长及模拟轴值。时间来自 SDL 原生事件时间与服务单调时钟，不代表游戏内部帧时间或绝对精准的硬件时间。约每 16ms 处理一次事件队列，保留同一批次内的按下与松开，避免只读取最终状态漏掉短按；界面给予短按约 70ms 的可见高亮，TXT 不因此延长按住时长。模拟轴采用最新值合并，通常至少间隔 50ms、变化达到 0.025 才记录，回到零点总会记录。驱动未上报的短按、两次采集间的模拟轴快速往返仍可能遗漏。

开始前已按住的键写入初始状态，不生成孤立的松开事件。结束时仍按住的键补记“停止时补记（非实际松开）”。设备断开、重连产生新的连接代次、切换设备、隐藏桌宠、切换离开手柄界面、采集连接失败或缓存中断都会结束录制；应重新开始下一轮。采集环形缓存为 256 个状态快照（空闲约 4 秒；密集按键事件会缩短覆盖时间），前端长时间卡顿会停止录制，避免把缺失数据当成完整记录。

记录约达 50,000 条会自动停止，单次采样可使条数略超过上限，随后最多补 26 个按住结束标记。记录保存在内存，不自动上传或自动落盘。结束后切换界面仍可返回导出；清除、新一轮录制和退出会清理记录，请及时导出。没有操作回放或自动输入功能。

保存位置由 WebView2 下载设置决定，通常在 `%USERPROFILE%\Downloads`；迁移过“下载”或选择另存目录时，以实际位置为准。结束录制并不会自动生成文件。

## 单 EXE 与运行文件

仍可只把发布页的 `Wuwatappo_Helper.exe` 发给其他人。EXE 已内嵌修改后的桌宠、SDL3 x64 运行库及手柄界面，接收方无需自行复制 SDL DLL。Windows 10/11 x64 需有 .NET Framework 4.x 和 WebView2 Runtime。

启动时解出运行文件到 `%LOCALAPPDATA%\Wuwatappo_Helper\runtime\<版本及摘要>\`，并校验内嵌资源。不要直接运行这里面的 `WuwaTappo.exe`，否则不会启动手柄采集服务；使用发布的外层 Helper EXE。可移动分发用的 EXE，但运行时仍会创建上述缓存。退出所有相关进程后可以删除旧版本运行缓存，下次需要时重新释放。

界面与原生采集通过本机 `127.0.0.1:48642` 通信，只监听回环地址，不对局域网开放。界面隐藏后会停止请求，原生高频状态采样随后暂停；设备热插拔检查继续。这个新增服务不请求账号业务接口，也不主动上传录制。

## 常见问题

- **手柄完全没有反应**：先用 `joy.cpl` 排查连接，再检查 PC/XInput 模式；先 USB 后蓝牙。确认启动的是新版外层 Helper EXE。
- **看到两个同名或 Xbox/PS 设备**：可能同时存在实体 HID 和转译软件的虚拟设备；点击设备名选择其中一个，避免在其他工具中重复转译。
- **PS 显示为 Xbox**：转译软件可能把 PS 转为 XInput。可选 PS 文字布局，但实际控件以当前输入模式为准。
- **轴、方向、扳机不对**：通用设备先学习轴，再设置反向、中心和扳机两端；必要时恢复默认。
- **“手柄服务未连接”**：退出所有旧版及托盘进程，使用完整新版 EXE；端口被占用、运行缓存被拦截、WebView2 的本机连接策略都可能造成失败。不要为此关闭整个防火墙。较新 WebView2 的本机网络访问策略可能变化，见 [Microsoft 官方说明](https://github.com/MicrosoftEdge/WebView2Announcements/issues/126)。隔离 Edge 测试仅向测试应用域授予了本机连接权限，未更改系统策略；完整 WebView2 实机仍待确认。
- **切换游戏窗口后是否还能显示**：已设置 SDL 后台事件采集提示，不要求手柄界面获得焦点，但桌宠和手柄界面需要保持显示。独占输入、游戏、驱动或转译软件可能影响结果，尚无真实游戏/实体手柄实测结论。
- **导出前退出了程序**：内存记录无法恢复，下次请先结束并导出 TXT。

## 开发构建与核验

原程序仍严格校验官方 1.0.3 文件摘要。新增启动器使用 Windows .NET Framework C# 编译器。构建前从 [SDL 官方 3.4.18 发布页](https://github.com/libsdl-org/SDL/releases/tag/release-3.4.18) 获取 `SDL3-3.4.18-win32-x64.zip`，将其中 SDL3.dll 放到仓库上一级的 `Wuwatappo_Helper-tools/SDL3-3.4.18/runtime/SDL3.dll`；文件 SHA-256 必须为：

```text
2b4b128d8d510cc2d442693cf848c050d700d43dc667afe9e5fd82b0570d667e
```

`scripts/build-controller-host.ps1 -SdlPath <DLL路径> -OutputDirectory <目录>` 可单独选择 DLL 路径。构建会校验 DLL 摘要和嵌入资源的逐项摘要，拒绝未知版本；SDL 的 zlib 许可证随包保留。

`node scripts/test-controller-core.cjs` 测试归一化、校准、同时输入、松开、采样与 TXT；`node scripts/test-controller-service.cjs` 以 `--probe` 启动不打开桌宠的短时测试服务，验证实际 SDL 初始化、来源限制、模块加载和模拟 UI 操作。测试不读取真实用户的键盘、鼠标记录，不调用账号业务接口。报告明确区分模拟验证与实体硬件验证。

相关资料：[XInput / DirectInput](https://learn.microsoft.com/en-us/windows/win32/xinput/xinput-and-directinput)、[SDL PS4](https://wiki.libsdl.org/SDL3/SDL_HINT_JOYSTICK_HIDAPI_PS4)、[SDL PS5](https://wiki.libsdl.org/SDL3/SDL_HINT_JOYSTICK_HIDAPI_PS5)、[SDL 后台事件](https://wiki.libsdl.org/SDL3/SDL_HINT_JOYSTICK_ALLOW_BACKGROUND_EVENTS)、[北通鲲鹏 20 厂商说明书](https://fcc.report/FCC-ID/2AWMK-BTP-KP20/7883300.pdf)、[飞智帮助中心](https://help.flydigi.com/docs/fk6fgtexhroeq72d)。具体型号以各厂商当期说明为准。
